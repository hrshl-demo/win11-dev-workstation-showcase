    Setup and modules

    Phase 3: Verify and enterprise acceptance

    Phase 3: save/reopen when needed, inspect real Verify results and accept the actual intended extension profile. CLI presence is not enterprise routing or runtime-health proof.

    Documented⏱ Environment refresh and acceptance are human checks$ Read-only Verify; no provider restorationWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    APurpose and place in the demo

    Separate known setup outcomes from real laptop acceptance before Restore or daily development.

    New environment values may not reach an already open VS Code process. Retain installed tools and refresh the application, not global PATH or policy.

    BStarting state

    Selected module/vendor/restart outcomes are known; no setup/app/test/Restore task still running. Save all editor work before a full exit.

    CExact actions

    1. YYou / IT

      Save work and refresh VS Code's environment when needed

      Save all work›Fully exit VS Code›Reopen from Windows

      A new terminal or Reload Window is not guaranteed to refresh values inherited by an existing VS Code process. Fully exit/reopen from Windows when required, keeping the intended profile and approved routing.

      Do not reinstall discovered Python 3.14/pwsh or globally alter PATH/JAVA_HOME to mask a stale process environment.

      You should see

      Fresh application environment with the same retained tools/settings/profile, not an assumed successful setup.

    2. >Human terminal

      Read required Verify results and selected locations

      Terminal›Run Task›Verify

      Post-setup required FAIL/exit 1 means not accepted. Verify checks required core tools, Python 3.14, current Java 25, exact Go 1.27.3, Node LTS 22/24/26 and WSL 2.9.3+ with wslc presence, reporting selected locations.

      Json emits a results array only. IncludeJavaModernization checks the optional thirteenth extension and does not select Java 11. RunConfigTest is separately approved legacy provider-restoring configuration testing, not normal modular acceptance or an agent/daily check.

      You should see

      Actual exit code/results. Tool presence, including wslc, does not prove runtime health, source policy or sign-in.

    3. YYou / IT

      Accept the intended profile, required IDs and approved source

      VS Code›Extensions›Intended approved profile

      Required 12Optional 13th only for modernization
      ms-python.python; vscjava.vscode-java-pack; golang.govscjava.migrate-java-to-azure
      ms-azuretools.vscode-azureresourcegroups; ms-azuretools.vscode-azure-github-copilotNot part of default acceptance
      ms-azuretools.vscode-bicep; ms-azuretools.vscode-containersIncludeJavaModernization is explicit
      ms-vscode-remote.remote-containers; ms-vscode-remote.remote-wslLegacy Java 11 selection remains separate
      GitHub.vscode-pull-request-github; ms-vscode.powershell; redhat.vscode-yamlNever install it to turn a default check green

      Check actual enabled state, intended profile and corporate source routing. Recommendations and workspace settings are not policy enforcement. An extension ID list or private-marketplace banner alone is not acceptance.

      F
      Field note human-only · Human action is separate

      A command shown here is instructional text, not authorization for an agent. Setup/module preview, repair, Restore, app/container launches, sign-in and deployment are human-operated decisions.

      Source-bound operating boundary; not a laptop observation.

      GitHub authentication/Copilot access are separate human decisions; Verify does not inspect or repair accounts.

      You should see

      Required Verify exit 0 plus genuine profile/source/enabled-state acceptance before explicit Restore.

    DCopyable material

    EExpected result

    Observed accepted laptop readiness or explicit blockers. The repository can be code-ready while the laptop remains unverified.

    FVerify and recover

    How to confirm success

    Record current results, selected runtime paths and actual intended-profile acceptance; then continue to explicit Restore.

    If something goes wrong

    Required Verify FAIL after intended setupRepeat with care
    Likely cause
    Missing/mismatched output, stale environment or unresolved setup result
    What to do
    Do not claim accepted. Read selected paths/version and safely refresh VS Code or review the failed named module with IT; no blind reinstall.
    Extension IDs exist but intended profile/source is unsupportedDo not repeat
    Likely cause
    CLI listing does not establish enabled-state or corporate routing
    What to do
    Stop acceptance and require compatible IT-managed automated delivery. No public VSIX/profile/source bypass.
    wslc exists but runtime operation failsDo not repeat
    Likely cause
    Presence is not health/policy proof
    What to do
    Stop the runtime action and report it; do not switch to a different runtime to bypass the failure/denial.

    Safe recovery

    Use read-only Verify/source review and preserve tools/settings/accounts/distro data. ConfigTest, Restore and setup are separate human-approved actions, not recovery hidden in Verify.

    Limits of this check

    Verify does not accept enterprise routing, licensing, authentication, real app requests or AKS protections automatically.
