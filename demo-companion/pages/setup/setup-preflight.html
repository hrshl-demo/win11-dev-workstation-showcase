    Setup and modules

    Phase 1: read-only Preflight

    Phase 1: actual prerequisite results before a human selects setup. Preflight does not install, repair, authenticate or verify all application readiness.

    Documented⏱ HTTPS outer budgets: 213 / 393 / 663 seconds$ Read-only network probes after approvalsWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    APurpose and place in the demo

    Expose missing prerequisites, policy and reachability before individually approved module actions.

    A failed or skipped read-only gate stays failed/NOT RUN; no installation is performed to make the check pass.

    BStarting state

    Phase 0 approved; supported effective script policy, reviewed root checkout and approved endpoint/network routing.

    CExact actions

    1. >Human terminal

      Run the real Preflight task

      Terminal›Run Task›Preflight

      Require no FAIL and exit 0 plus the Phase 0 human approvals. Missing WSL/wslc before setup can be an expected WARN; read the actual messages.

      You should see

      Observed read-only prerequisite results, not installed tools, approved extension state or authentication.

    2. YYou / IT

      Understand timeout selection and outer budgets

      Preflight task›HTTPS timeout picker

      Per-request selectionSix-host outer child budgetMeaning
      5 seconds (default)213 secondsNormal request setting, not setup completion time
      15 seconds393 secondsApproved slower route; select it again for setup
      30 seconds663 secondsUp to about 11 minutes for the outer probe budget

      Transient timeout/DNS/connect errors may retry at most three attempts with 250 ms backoff. Denial/certificate errors do not get those retries; redirects are not followed. Root 404/405 establishes reachability only, not package/source success.

      A standalone Preflight selection is not cached. Choose the same reviewed slow value for the following named setup if needed; installer waits are a different budget.

      You should see

      A truthful timeout/reachability result without interpreting a root response as installation permission.

    3. >Human terminal

      Optional pre-setup Verify is inventory, not acceptance

      Terminal›Verify results

      Before setup, missing expected outputs may yield exit 1. This optional inventory is not the Preflight installation gate. After intended setup, a required FAIL/exit 1 means not accepted.

      You should see

      Missing pre-setup outputs correctly labelled as inventory gaps, never hidden or confused with post-setup success.

    DCopyable material

    Every command and message for this page sits inside its step, next to the explanation, with its own Copy button.

    EExpected result

    Approved prerequisites plus observed Preflight outcomes. Continue only to a reviewed human module inventory/confirmation, not a broad automatic setup run.

    FVerify and recover

    How to confirm success

    Record actual exit code and messages. No FAIL/exit 0 is necessary but does not establish source/profile licensing or a working app.

    If something goes wrong

    HTTPS timeout on a slow approved routeRepeat with care
    Likely cause
    Transient DNS/connect/request delay
    What to do
    Human may choose documented 15/30-second selection for both Preflight and the following named module. Retain policy and inspect the real result.
    Certificate/proxy/source denialDo not repeat
    Likely cause
    Untrusted certificate or imposed network/source policy
    What to do
    Stop and use IT-approved routing; do not disable validation, follow redirects, switch sources or bypass proxy policy.
    Optional Verify reports missing WSL/runtime before setupSafe to repeat
    Likely cause
    Expected pre-setup outputs are absent
    What to do
    Keep the gap explicit and review the necessary named module only after prerequisites and approvals.

    Safe recovery

    Use source/mocks for blocked scripts; preserve all installed state. A retry is read-only only if the command is actually Preflight/Verify, not module preview or configuration testing.

    Limits of this check

    Preflight does not prove vendor installer state, extension enablement/profile routing, package restore, user sign-in, WSL runtime health or Azure approval.
