    Setup and modules

    Phase 2: installed-first named modules

    Phase 2: installed-first independent modules. Retain compatible installed versions/settings, stop unknown/incompatible inventory before downloads, and never call the broad Microsoft bundle normal setup.

    Documented⏱ Per target: 7200s default; selectable 3600/7200/14400s$ Separately approved package/licence choicesWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    !
    Separate human approval required. Human direct tasks or human-selected local Workstation setup only, with scoped approvals/native confirmations. Ordinary agents use source/mocks. No repair, automatic elevation/restart, policy/source bypass, upgrade or hidden Restore.

    APurpose and place in the demo

    Choose only missing tools and independently approved SDK/extension/WSL modules without rewriting the machine's installed state.

    All module targets are inventoried before any download/source/provider/installer activity. Missing targets are rechecked after approval; known installed targets are retained rather than redownloaded/upgraded.

    BStarting state

    Phase 0 decisions and successful Preflight, safe reviewed checkout, previous vendor installers known stopped/completed, and an approved restart window if needed.

    F
    Field note partial · Stopped partial is not success

    Do not use Finish/SkipBase after a stopped partial legacy base. Preserve tools, settings, accounts and distro data; establish vendor/reboot state and use reviewed installed-first inventory.

    Source-bound operating boundary; not a laptop observation.

    No-module bootstrap is nonmutating Core preview. Setup preview/User-run setup select one module; there is no blanket normal Microsoft preset.

    CExact actions

    1. AAgent: named scope

      Select the local agent once, then approve real stages

      VS Code Chat›Local Windows session›Workstation setup

      The native repository agent reads existing scripts/catalog/tasks, checks prior installer/reboot safety, inventories before network Preflight, and invokes only needed sequential modules. It explicitly separates dependency Restore, no-restore checks and approved local startup/requests; you do not pick every task or paste every command.

      F
      Field note human-only · Human approval is separate

      A shown command is not authorization. Humans may run tasks directly or select Workstation setup in local Windows VS Code, approve installation/Restore/launch scopes and answer native confirmations. Ordinary coding/build/desktop/cloud/subagents cannot do those actions. Repair, policy/source/account/profile changes, automatic elevation/restart, Git publication, cleanup and cloud execution remain outside that agent.

      Source-bound operating boundary; not a laptop observation.

      The human approves scoped installations/downloads/launches and answers native prompts. WSL changes, Ubuntu, licensed Docker, modernization and images are separate decisions. Missing interactive tools/prompts stop at the exact blocker; the agent never types approval answers or suppresses permissions.

      Resume only after known installer/vendor/reboot outcomes. Refresh inventory and approvals, never blindly retry or infer success from cancellation/logs/exit 0. Default local Python/current Java/Go acceptance does not hide missing WSL or unapproved full-profile/source state.

      You should see

      One human-selected local agent and auditable existing terminal work with real approval pauses. Live VS Code selection/tool/native-confirmation acceptance is not yet proven by static tests.

    2. YYou / IT

      Manual fallback: preview one needed named module

      Terminal›Run Task›Setup preview

      For manual operation, select Core, Python, Java, Go, Extensions, WSL, Ubuntu, Docker or Modernization. Review all target version/location/inventory states before any apply decision.

      !

      Compatible installed: retain/skip before download. Registered incompatible or unknown: retain and stop without downloads. Aliases/caches or arbitrary unknown portable paths are not installation proof.

      You should see

      A local installed/missing/unknown plan, not an executed install or blanket agent permission.

    3. YYou / IT

      Core: confirm only genuinely missing targets

      Terminal›Run Task›Install core tools

      Core covers VS Code, Git, GitHub CLI, Copilot CLI, uv, PowerShell 7, Node LTS, Azure CLI, azd and kubectl. Existing compatible versions/settings/accounts are retained; no automatic upgrades or global PATH/profile/Copilot changes.

      You should see

      Per-target retained/installed/stopped outcomes. No fonts, PowerToys, NVM, Explorer/taskbar or other broad global tweaks.

    5. YYou / IT

      Extensions require approved existing routing

      Terminal›Run Task›Install extensions (approved source)

      Human/IT attests the existing CLI/default-profile route before ExtensionSourceApproved. That flag is not a source override, acceptance proof, or a way to bypass corporate marketplace policy.

      Install only genuinely missing required IDs through the supported approved automation; twelve required extensions must still be accepted in the actual intended profile.

      You should see

      Supported approved missing-extension delivery, while retaining accounts/profile/settings.

    6. YYou / IT

      If the private marketplace path is unsupported, stop

      IT-managed extension delivery›Intended profile

      ✕

      A private-marketplace banner proves neither denial nor compatibility. If existing CLI/profile routing is unsupported, stop acceptance. IT must supply compatible managed automated delivery; no public VSIX/source/account/profile bypass or twelve manual installs.

      You should see

      An explicit blocker and supported IT path, never a green acceptance inferred from a CLI list.

    7. YYou / IT

      WSL: inspect features and restart state before payloads

      Terminal›Run Task›Install WSL components

      Use an approved Administrator context for feature actions when required; no automatic elevation. DISM is no-restart. Required/pending restart pauses before further downloads. Existing WSL runtime, distros, defaults and data are retained.

      No silent WSL update, distro reset/launch or automatic reboot. wslc presence is not proof of runtime health or policy acceptance.

      You should see

      Explicit feature/runtime result or stopped-for-restart outcome; never a partially completed module reported as complete.

    8. YYou / IT

      Optional modules remain separate decisions

      Terminal›Run Task›Optional named module

      Ubuntu is a separate optional module only after WSL/features/restart readiness. Docker Desktop requires explicit licensing approval. Modernization is Java 11 plus the optional thirteenth extension; it is not a manual upgrade of the legacy application.

      ✕

      Legacy Microsoft bundle (optional) is broad upstream opt-in, not normal setup or partial-run recovery. Finish setup/Legacy SkipBase require confirmed successful legacy base plus reboot/resume. A force-closed original base is stopped partial, not successful completion or rollback.

      You should see

      Only the selected approved optional scope; installed shared tools/settings/accounts/distros remain retained.

    9. YYou / IT

      Observe target events, timeouts and uncertain vendor state

      Setup terminal›.showcase-setup module events

      Read streamed target status, elapsed time, actual exit codes and the final module result. Per-target wait defaults to 7200 seconds; picker 3600/7200/14400, direct accepted range 300-14400. Those are wait limits, not completion promises.

      Non-secret state/elapsed events live in .showcase-setup\module-*.jsonl, not raw request/vendor-output logging. Timeout/cancellation can leave elevated vendor-child state uncertain; do not blindly retry or kill all similarly named processes.

      For the separately chosen legacy bundle, its base wait picker is 7200/14400/28800 seconds, default 14400. PID/lock/log activity is not success: final summary, flagged steps, key dismissal and actual reboot/resume matter.

      You should see

      A known complete/stopped/failed/uncertain result. Pause before the next module if vendor or restart state is unresolved.

    EExpected result

    A truthful per-module installed-first outcome with existing compatible state retained. Setup modules themselves never Restore or launch; the named agent's later Restore/launch stages need separate approval. It never signs in or deploys.

    FVerify and recover

    How to confirm success

    Only after known module/vendor/restart outcomes, proceed to save/reopen and Verify. Actual required readiness and intended extension profile acceptance are still necessary.

    If something goes wrong

    Installed tool is invisible in the current terminalRepeat with care
    Likely cause
    Stale VS Code environment or known registration/path not represented on PATH
    What to do
    Use reported installed version/location. Save work and fully exit/reopen VS Code from Windows as appropriate; no reinstall or global PATH edit.
    Inventory is incompatible or unknownDo not repeat
    Likely cause
    Registered state cannot safely satisfy the manifest
    What to do
    Retain it and stop before downloads. Report the mismatch for approved review; no automatic upgrade/replacement.
    Timeout/cancellation or pending restartDo not repeat
    Likely cause
    Vendor/elevated child completion or Windows feature state is uncertain
    What to do
    Stop further module downloads/retries. Establish the actual owned vendor/restart outcome with IT; no mass termination or automatic reboot.
    Stopped legacy base followed by a Finish requestDo not repeat
    Likely cause
    Partial setup mistaken for successful base/reboot/resume
    What to do
    Do not run Finish/SkipBase. Preserve all installed state, inspect outcomes, and use reviewed installed-first module inventory for genuine missing targets.

    Safe recovery

    Use stopped-partial recovery, never rollback or broad uninstall. Ordinary agents use source/AST/mocks only; the named local workflow resumes with fresh safety/inventory and new scoped approvals, never repair.

    Limits of this check

    Hosted mock tests do not prove this laptop's vendor install, source/profile routing, runtime health, licence, restart or package readiness.
