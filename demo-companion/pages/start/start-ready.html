    Start safely

    Phase 0: approvals and safe clone

    Phase 0 comes before scripts. Keep a new or existing clone safe, review corporate routing and separate repository readiness from laptop acceptance.

    Documented⏱ IT approvals are not timed installation promises$ Licences and available disk/network must be approvedWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    APurpose and place in the demo

    Make prerequisites and human decisions visible before setup.

    This guide does not install Git/VS Code, authenticate, update another clone, change policy or infer machine readiness from CI.

    BStarting state

    Supported serviced Windows 11 build 22621 or later, virtualization/nested virtualization as applicable, at least 15 GB free plus SDK/image/distro budgets, approved UAC/licensing/restart window.

    App Installer/WinGet registered for the signed-in user, approved CLI/configuration/source routing, network/proxy/TLS/Authenticode and script execution policy. Git/VS Code and private-repo access must already be available before cloning.

    CExact actions

    1. YYou / IT

      Confirm actual prerequisites with IT

      IT prerequisite review›docs\IT-PREREQUISITES.md

      • Review Windows service/build support, virtualization, disk budgets and approved tool/licence choices.
      • Confirm App Installer/WinGet source/configuration support, approved corporate proxy/TLS and extension CLI/default-profile routing.
      • Confirm private GitHub access and a Copilot entitlement separately; neither setup nor Verify signs you in.
      You should see

      Explicit approved decisions or a prerequisite blocker, not permission to work around policy.

    2. >Human terminal

      Inspect effective script policy without changing it

      Integrated PowerShell›Read-only policy inspection

      All scopes Undefined can still resolve to Restricted. If blocked, record the script check NOT RUN and inspect source/mocks. Only a human, after explicit IT approval for an unset/default restriction, may consider the documented CurrentUser RemoteSigned route. It is not a Group Policy/AllSigned bypass.

      ✕

      No agent policy change, process/child-shell override, Bypass, blanket unblock, elevation or restart. Retain imposed controls.

      You should see

      All scopes and effective policy understood; no machine/user/process policy changed.

    3. YYou / IT

      Clone and review Workspace Trust

      VS Code›Source Control›Clone Repository

      1. Use Source Control: Clone Repository, or Ctrl+Shift+P: Git: Clone, with the authorized private repository URL.
      2. Choose your own approved new folder; open it only after source review.
      3. Review README, AGENTS.md, .github instructions and Workspace Trust. Trust is a decision, not automatic permission to run tasks.
      Open Private workstation repository ↗
      You should see

      A separately reviewed checkout. Never modify the user's primary clone or another active session as a demo shortcut.

    4. YYou / IT

      For an existing clone, update only when safe

      Save work›Source Control›Reviewed incoming main

      1. Wait for setup/resume, app/test/Restore tasks and agent edits to finish; save all unsaved editor work.
      2. Inspect status, branch, approved remote and incoming source. If dirty/shared/active, use a separate reviewed checkout instead.
      3. Only a clean reviewed main can be explicitly updated fast-forward; do not reset, auto-stash, discard files or switch someone else's active branch.
      You should see

      Preserved staged, unstaged, untracked and unsaved work, with actual source identity reviewed.

    DCopyable material

    Every command and message for this page sits inside its step, next to the explanation, with its own Copy button.

    EExpected result

    A supported, approved starting state and safely reviewed source checkout. This is not a claim that runtime/extension setup is complete.

    FVerify and recover

    How to confirm success

    Confirm every prerequisite/approval; then choose Preflight. Save actual observed results separately from this guide's ticks.

    If something goes wrong

    Execution policy blocks scriptsDo not repeat
    Likely cause
    Effective Restricted, AllSigned or imposed policy
    What to do
    Report NOT RUN; inspect source and ask IT through approved processes. Never bypass the imposed policy.
    Existing clone is dirty or still running tasksDo not repeat
    Likely cause
    Unsaved/unrelated work or active setup/app/Restore
    What to do
    Retain everything; wait or use a separate reviewed clean checkout. Do not switch/reset/update it.
    Private marketplace or GitHub access is uncertainRepeat with care
    Likely cause
    Approved routing/entitlement is not established
    What to do
    Stop acceptance and obtain supported IT-managed delivery/access. No public VSIX, account/profile/source workaround.

    Safe recovery

    Use non-destructive recovery. Missing approval is a blocker, not permission to repair/install or use the legacy bundle.

    Limits of this check

    The page and existing hosted CI do not inspect this laptop, effective profile, credentials, virtualization state or disk.
