    Developer workflow

    Phase 4: Restore once, check daily

    Phase 4: explicitly materialize pinned project dependencies once, then use dispatcher-guarded daily Test/Lint/Coverage without downloads or restoration.

    Documented⏱ Restore is a separate acquisition window; daily checks depend on existing prerequisites$ Human-approved package/network acquisition onlyWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    !
    Separate human approval required. Restore is a separate human-approved acquisition stage, directly or through named local Workstation setup with native confirmation. Ordinary agents never Restore. Daily checks never acquire even cached packages; missing runtimes/providers stop.

    APurpose and place in the demo

    Keep setup, explicit package acquisition and reproducible daily verification separate.

    Installed runtimes and already restored project dependencies are prerequisites. Offline mode alone may still restore cached packages; use the no-restore dispatcher guards.

    BStarting state

    Post-setup Verify and actual approved profile/source acceptance, required runtimes and human-reviewed project manifests/lockfiles. Save work and ensure no competing setup/app/Restore tasks.

    CExact actions

    1. YYou / IT

      Approve explicit Dependencies Restore and the samples

      Workstation setup approval or manual Restore project dependencies task

      1. Approve RestoreTarget Dependencies and the named samples. Manual All includes Python/Java/Go/PowerShell, never Legacy; the agent defaults to the three current application samples.
      2. Review and explicitly confirm package/network acquisition. Runtimes/provider prerequisites must already exist.
      3. The named local agent can invoke each approved Restore task; ordinary agents cannot. Restore is never hidden inside daily Test/F5.
      You should see

      Pinned project environments/dependencies or a truthful unmet prerequisite; no silent installation to make Restore succeed.

    2. YYou / IT

      Understand what is restored and what is not

      Sample manifests›Project-local outputs

      SampleExplicit Restore materializesExisting prerequisite
      PythonHash-locked uv environment in .venvPython 3.14 and uv
      Current JavaPinned Maven wrapper distribution/plugins/dependenciesJDK 25 and approved wrapper prerequisites
      GoDeclared project dependencies; standard-library sample needs no external moduleManifest-defined Go 1.27.3, no automatic toolchain download
      PowerShellProject-local Pester 5.7.1 and PSScriptAnalyzer 1.24.0Installed PowerShell and existing NuGet/provider prerequisites

      Legacy Java 11/Boot 2.7 is an explicit separate exercise. Do not substitute a runtime, add legacy to All or install missing providers. PowerShell test-module Restore is an additional approved agent scope.

      You should see

      Known restored outputs with runtime/dependency versions distinguished; project-local is not unapproved acquisition permission.

    3. >Human terminal

      Run daily no-restore Test, Lint and Coverage

      Repository root›Terminal›Run Task

      Use focused Test/Lint/Coverage Python/Java/Go/PowerShell tasks as needed. The dispatcher prevents uv synchronization/Python download, Maven wrapper/plugin/dependency acquisition and Go toolchain/module downloads. Missing prerequisites mean NOT RUN, not pass.

      Direct sample commands belong inside the named sample directory with the required installed/restored environment. Do not copy a bare uv/wrapper command from a general table and allow an implicit download.

      You should see

      Observed results, failures and NOT RUN reported separately. No agent installs/restores to make checks pass.

    4. YYou / IT

      Inspect reports and the approved Testing view

      VS Code›Testing›Actual report files

      SampleReport paths relative to that sample
      Pythontest-results.xml; coverage.xml; htmlcov\index.html
      Javatarget\surefire-reports; target\site\jacoco\index.html and jacoco.xml
      Gotest-results.json; coverage.out; coverage.html
      PowerShellRepository-root artifacts\pester.xml

      Select the locked Python .venv interpreter and correct Java 25/approved Go test tooling. UI discovery is not proof that a pinned-environment check ran. PSScriptAnalyzer/mock/AST checks inspect scripts without executing state-changing entry points.

      You should see

      Actual current reports and truthful runtime/source attribution, not screenshots or stale files presented as live.

    DCopyable material

    Every command and message for this page sits inside its step, next to the explanation, with its own Copy button.

    EExpected result

    A separate confirmed Restore stage followed by daily checks that either run against existing prerequisites or explicitly report NOT RUN.

    FVerify and recover

    How to confirm success

    Observe exit codes/results and current report outputs. Keep runtime/version attribution, failures and skips visible; never equate a list of commands with passing checks.

    If something goes wrong

    Daily check reports missing runtime/dependency/moduleDo not repeat
    Likely cause
    Setup or explicit Restore prerequisite is absent
    What to do
    Report affected command NOT RUN. Only the named local workflow can return to a separate human-approved acquisition stage; ordinary agents never acquire it.
    Offline command still attempts cached synchronizationRepeat with care
    Likely cause
    Offline mode alone is not a no-restore guarantee
    What to do
    Stop the direct invocation and use the existing dispatcher guards with already restored dependencies; do not weaken or bypass them.
    Old report exists but current command did not runSafe to repeat
    Likely cause
    Stale generated evidence
    What to do
    Label its date/revision/runtime and do not claim it proves the current pinned environment or laptop.

    Safe recovery

    Preserve environments/module/cache trees and source. No broad deletion/reinstall or hidden Restore. Check prerequisites read-only and use safe recovery.

    Limits of this check

    Daily in-process tests and hosted CI do not establish a live service/container request, enterprise source/profile acceptance or AKS deployment.
