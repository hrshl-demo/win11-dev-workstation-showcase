    Developer workflow

    Phase 5: human-run synthetic samples

    Phase 5: the human launches prepared samples, then checks health and synthetic contracts. F5 and RunContainer must not hide package/helper/image acquisition.

    Not rehearsed⏱ Human startup/readiness unknown; never repair during the demo$ Existing approved runtimes/imagesWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    !
    Separate human approval required. Application/container launches, requests and image Restore are separate human operations. Agents and this HTML never start apps/containers/servers or acquire missing tools.

    APurpose and place in the demo

    Demonstrate a real synthetic request only after a separately approved human launch.

    All expected values below are documented examples, not observed laptop output. Source CI/in-process tests are different evidence from a real running service.

    BStarting state

    Accepted runtime/profile, already restored/tested project, available intended ports and a human willing to operate the launcher. No competing setup/Restore work. Container mode additionally needs an existing explicitly restored image and approved runtime.

    CExact actions

    1. YYou / IT

      Choose a prepared local sample and confirm the launch

      Terminal›Run Task›Named local task

      Actual labels are Run EMI API (local), Run IFSC service (local) and Run FX rates (local). They select ports 8080, 8081 and 8082 respectively. Keep the launcher terminal open; inspect its actual endpoint/startup, not an assumed service.

      You should see

      An observed startup or truthful NOT RUN. Stop only the specific owned task with Ctrl+C, not every similarly named process.

    2. >Human terminal

      Use a second terminal for health and synthetic contracts

      Second VS Code integrated PowerShell terminal

      Sample taskSynthetic request at its selected portDocumented expected result, not observed
      EMI / 8080POST /emi: principal 2500000.00, annual_rate_percent 8.5, tenure_months 240emi "21695.58"; total_payment "5206939.20"; total_interest "2706939.20"
      IFSC / 8081GET http://localhost:8081/ifsc/abcd0123456Normalizes ABCD0123456; valid true. Syntax only, no bank/branch/payment proof
      IFSC / 8081GET http://localhost:8081/ifsc/ABCD1123456HTTP 200 validation result, valid false: fifth character must be zero
      FX / 8082GET http://localhost:8082/convert?from=USD&to=INR&amount=100"8800.00" and INR ₹8,800.00; fixed synthetic rate, not market data

      Each task's /health should return {"status":"ok"} at the reported port. Sample READMEs' direct default-port examples use 8080; use the actual task-selected port for IFSC/FX. Python also exposes /docs and /openapi.json.

      EMI INR displays: ₹21,695.58; ₹52,06,939.20; ₹27,06,939.20. Money is fixed two-decimal JSON strings with exact arithmetic and half-up rounding, not binary floating point.

      You should see

      Only actual observed responses establish this live run; absent startup/response stays unavailable.

    3. YYou / IT

      F5 requires existing debugger and project readiness

      Run and Debug›FastAPI EMI / Spring Boot IFSC / Go FX

      • FastAPI EMI uses the existing pinned .venv/debugpy and port 8080.
      • Spring Boot IFSC uses the approved current JDK 25/restored-tested project and port 8081.
      • Go FX uses existing approved Delve and the pinned Go toolchain, port 8082.

      No F5 helper install, dependency restoration, runtime substitution or Dev Container acquisition. Missing debugger/prerequisite means NOT RUN, not download.

      You should see

      A human-operated debug session using existing prerequisites, or an explicit missing prerequisite.

    4. YYou / IT

      Container acquisition/build belongs only to explicit Restore

      Terminal›Restore project dependencies›ContainerImages

      Human chooses the intended sample and approved runtime, reviews network/image build and explicitly confirms RestoreTarget ContainerImages. All means the three modern application images, not PowerShell or legacy.

      Auto selects wslc first and considers Docker only if wslc is absent. Explicit runtime probes only that selected approved runtime; no fallback after failure/denial. Docker remains licence-reviewed optional.

      You should see

      An existing approved local image before Run; no build/pull hidden in Run or F5.

    5. YYou / IT

      RunContainer inspects an existing image and never pulls

      Terminal›Run EMI API (container) / Run IFSC service (container) / Run FX rates (container)

      The actual container tasks prompt the runtime and confirm the launch; IFSC/FX tasks choose ports 8081/8082. RunContainer inspects the existing local image and uses --pull=never. Missing images mean NOT RUN, not a build/pull/restoration fallback.

      A Dev Container reopen can acquire an image and is not the no-restoration daily route. Do not change a blocked/broken WSL operation into a policy-bypassing Docker fallback.

      You should see

      Actual human-owned startup and synthetic request, or a truthful stop; no surprise acquisition.

    DCopyable material

    Every command and message for this page sits inside its step, next to the explanation, with its own Copy button.

    EExpected result

    Real health/functional responses only when actually observed after human launch. No customer identifiers, account details or external bank/rate calls are needed.

    FVerify and recover

    How to confirm success

    Record the exact source/runtime/date, actual task endpoint, health and synthetic contract response. Keep historical/in-process evidence labelled separately.

    If something goes wrong

    Port occupied or service never reaches healthRepeat with care
    Likely cause
    An unrelated listener or failed/unfinished owned startup
    What to do
    Read the task outcome and preserve unrelated processes. Human may choose a documented distinct port or stop the known owned task; agents do not launch/retry.
    Missing image or debuggerDo not repeat
    Likely cause
    Explicit earlier image Restore or approved helper prerequisite absent
    What to do
    Report NOT RUN. The human decides the separate approved acquisition stage; no live install/Restore/F5 workaround.
    Installed wslc operation is failing or policy-deniedDo not repeat
    Likely cause
    Runtime health/policy prerequisite not satisfied
    What to do
    Stop and show labelled evidence. Do not select Docker after that failure to bypass the boundary.

    Safe recovery

    Stop only the known owned integrated task with Ctrl+C. Preserve shared runtimes/accounts/distros/images and use a separate reviewed prepared checkout or clearly dated fallback evidence.

    Limits of this check

    No live service/container/F5/HTTP request was performed by the companion. Expected examples are not lender advice, market rates or real IFSC existence checks.
