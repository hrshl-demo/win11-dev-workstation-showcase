    Quick path: restore, check and run

    Phases 4-6. Start only after real laptop acceptance. Restore is explicit; daily checks and F5 never hide package, helper or image acquisition.

    Documented⏱ Rehearse before presenting; no completion guarantee$ Existing approved toolsWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    QQuick steps

    1. YYou / IT

      Start with an accepted environment

      Verify results›Intended VS Code profile

      1. Confirm pinned runtimes, enabled required extensions, approved source/profile and separately approved GitHub/Copilot access.
      2. Keep unavailable commands NOT RUN; do not install to make a daily check pass.

      Details: Phase 3: Verify and enterprise acceptance · step 9b

      You should see

      Observed readiness, not the guide's progress ticks or old CI.

    2. YYou / IT

      Explicitly Restore project dependencies

      Terminal›Run Task›Restore project dependencies

      1. Choose Dependencies and the intended sample, or All for modern Python/Java/Go/PowerShell.
      2. Review network/package acquisition and confirm it yourself; legacy remains opt-in.

      Details: Phase 4: Restore once, check daily · step 2

      You should see

      Restored pinned environments/modules, with missing runtime/provider prerequisites reported.

    3. >Human terminal

      Run daily no-restore checks

      Terminal›Run Task›Test all samples / Lint all samples / Coverage all samples

      1. Use existing runtimes and already restored dependencies only.
      2. Read actual failures/skips and report outputs; offline mode alone is not enough to prevent cached restore.

      Details: Phase 4: Restore once, check daily · step 3

      You should see

      Observed pass/fail/NOT RUN and actual reports, not a copied command list.

    4. YYou / IT

      Approve a separate local launch

      Workstation setup approval or manual named local task

      1. Use prepared samples; tasks select ports 8080/8081/8082. Only the named local agent may invoke approved launches.
      2. Keep the owned launch terminal open and use another for requests.
      !

      Ordinary agents never launch; native confirmations remain human answers.

      Details: Phase 5: human-run synthetic samples · step 4

      You should see

      The actual endpoint or truthful NOT RUN; startup is not assumed.

    5. >Human terminal

      Check health and a synthetic request

      Second integrated PowerShell terminal

      1. Only after human-confirmed startup, run health and the documented synthetic request.
      2. Compare response strings/INR grouping; expected examples are not historical laptop observations.

      Details: Phase 5: human-run synthetic samples · step 5

      You should see

      Health status ok and EMI 21695.58 for the documented example, only if actually observed.

    6. YYou / IT

      Keep F5 and containers acquisition-free

      Run and Debug›FastAPI EMI / Spring Boot IFSC / Go FX

      1. F5 requires existing locked debugpy, correct JDK/restored project or approved Delve.
      2. Container builds belong only to confirmed Restore ContainerImages; Run inspects an existing image and uses --pull=never.

      Details: Phase 5: human-run synthetic samples · step 6

      You should see

      No hidden dependency/tool/image download; missing prerequisites are NOT RUN.

    7. YYou / IT

      Review, publish only authorized work, inspect exact-SHA CI

      Source Control›GitHub Pull Requests view

      1. Separate sign-in, commit/publish and PR decisions; stage only intended files and preserve the template.
      2. Observe every modern-service job/artifact on the actual SHA. Push/PR never deploys.

      Details: Phase 6: GitHub review and exact-SHA CI · step 7

      You should see

      A small reviewed change and genuine checks; optional AKS is a separate human approval path.
