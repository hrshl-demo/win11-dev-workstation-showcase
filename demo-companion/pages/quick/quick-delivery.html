    QQuick steps

    1. YYou / IT

      Confirm existing AKS/ACR and real inputs

      IT-owned existing resources›docs\GITHUB-AKS.md

      1. Require actual namespace/image values, registry/cluster identity, RBAC, kubelet pulls and connected equipped runners.
      2. Do not create resources, fetch tools, invent demo image defaults or enter secrets into HTML.

      Details: Phase 7: optional existing AKS and ACR · step 1

      You should see

      Real prerequisites or explicitly unset inputs; no claim of deployment readiness.

    2. AAgent: named scope

      Review application manifests only

      Kubernetes templates›Kubernetes manifest check

      1. Review non-root Deployments, probes, resource bounds and ClusterIP Services.
      2. Static checks use existing dependencies; no authentication, cloud calls, build/push or namespace creation.

      Details: Phase 7: optional existing AKS and ACR · step 2

      You should see

      Static evidence and missing inputs, not a live cluster validation.

    3. YYou / IT

      Require independently verifiable protections

      GitHub›aks-demo environment / deployment workflow

      1. Require independent reviewer, prevent self-review, no admin bypass and exact main-only rules.
      2. Verify the live controls/plan support; unavailable or unverifiable approval gates stop.

      Details: Phase 7: optional existing AKS and ACR · step 3

      You should see

      Fail-closed protection evidence, not an assumption based on YAML.

    4. GGitHub Actions

      Pin trusted current main and modern CI

      Reviewed main›Exact current source SHA›CI

      1. Use the current full main SHA, not this guide's dated source pin or demo-complete.
      2. Require successful modern-service checks and distinct OIDC registry/deploy identities.

      Details: Phase 7: optional existing AKS and ACR · step 4

      You should see

      Exact-SHA evidence; a push or PR never starts deployment.

    5. YYou / IT

      Only if separately authorized, dispatch manually

      Terminal›Run Task›Deploy AKS (manual main only)

      1. The human supplies the reviewed current SHA and explicitly confirms this separate action.
      2. Same-run immutable image digests must pass the independent approval gate; dispatch is not approval.
      !

      Agents and this HTML never dispatch, authenticate or deploy.

      Details: Phase 7: optional existing AKS and ACR · step 5

      You should see

      An actual approved workflow result or truthful failure/wait; no latest-tag fallback.

    6. YYou / IT

      Inspect status/logs/access within the existing namespace

      Terminal›Kubernetes status / Kubernetes logs / Kubernetes port-forward

      1. Use the existing approved user context, actual namespace and intended sample.
      2. Missing tools/network/approval means stop; do not fetch credentials, grant RBAC or create ingress.

      Details: Phase 7: optional existing AKS and ACR · step 6

      You should see

      Observed namespace-scoped outcomes or a documented NOT RUN.
