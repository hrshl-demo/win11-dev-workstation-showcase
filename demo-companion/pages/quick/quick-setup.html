    Quick path: setup and acceptance

    Phases 0-3. Select the approved local Workstation setup agent once, or use manual tasks. Existing tools are retained before downloads; checkmarks are not laptop acceptance.

    Documented⏱ Variable; approvals, downloads and restart may take much longer$ Approved/licensed choices onlyWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    !
    Separate human approval required. Only human-selected local Workstation setup may execute scoped approved setup/Restore/launch stages. Ordinary agents remain blocked. HTML never executes; no policy bypass or blind legacy resume.

    QQuick steps

    1. YYou / IT

      Approve prerequisites and review the clone

      IT review›VS Code›Source Control

      1. Confirm Windows 11, disk budget, App Installer/WinGet, approved Git/VS Code, source/profile policy and repository access.
      2. Virtualization is for optional WSL/containers, not Native. Save work; never update an active/dirty/shared clone.

      Details: Phase 0: approvals and safe clone · step 1

      You should see

      A reviewed safe main checkout and explicit prerequisite decisions, not installed-state proof.

    2. AAgent: named scope

      Select Workstation setup and send one start request

      Local Windows VS Code Chat›Agent dropdown

      1. Choose Workstation setup on the reviewed clone, not a cloud/remote or delegated agent.
      2. It inventories first and drives existing terminal tools; you approve changes and answer native prompts. The remaining task steps are the manual fallback.
      !

      Missing tools/interactive prompts block execution; do not enable autoapprove.

      Details: Phase 2: installed-first named modules · step 2a

      You should see

      Local demo and full workstation readiness remain distinct. Live agent/tool use still needs human acceptance.

    3. >Human terminal

      Run read-only Preflight

      Terminal›Run Task›Preflight

      1. Use 5 seconds normally, or the same approved slow HTTPS selection for Preflight and the following named setup.
      2. Require no FAIL and exit 0. Missing pre-setup WSL outputs may be expected warnings.

      Details: Phase 1: read-only Preflight · step 2

      You should see

      Actual prerequisite results, not installation or authentication.

    4. YYou / IT

      Manual fallback: preview the one module you need

      Terminal›Run Task›Setup preview

      1. Choose Core/Python/Java/Go/Extensions/WSL/Ubuntu/Docker/Modernization explicitly.
      2. Inventory all targets before any payload/source/provider/installer activity; installed compatible targets skip, unknown/incompatible stops.
      !

      Ordinary coding/build/desktop/cloud agents never execute preview/WhatIf.

      Details: Phase 2: installed-first named modules · step 3

      You should see

      Version/location-aware retained targets and only approved missing targets.

    5. YYou / IT

      Confirm only needed Core installs

      Terminal›Run Task›Install core tools

      1. Review local inventory and the single-module confirmation.
      2. Keep existing versions/settings. Normal Core is not the legacy Microsoft bundle.

      Details: Phase 2: installed-first named modules · step 4

      You should see

      Per-target retained/installed/stopped outcomes; no blanket success.

    6. YYou / IT

      Choose missing SDKs independently

      Terminal›Run Task›Install Python SDK / Install Java SDK / Install Go SDK

      1. Choose only the needed named SDK: Python 3.14, current JDK 25, manifest-defined Go 1.27.3.
      2. Known registrations/paths can find Python/pwsh despite stale VS Code PATH; unknown inventory stops without downloads.

      Details: Phase 2: installed-first named modules · step 5

      You should see

      Each SDK has its own reviewed result; no automatic upgrade or runtime substitution.

    7. YYou / IT

      Attest and select only approved missing Native extensions

      Workstation setup or existing Extensions terminal route

      1. NativeDemo selects five essential language/debugger IDs; the full twelve-extension module is separate.
      2. Human/IT attests existing CLI/default-profile routing; keep source/account/profile policy.
      !

      No public VSIX, source switch or manual-install workaround.

      Details: Phase 2: installed-first named modules · step 6

      You should see

      Selected IDs still need actual enabled-state/profile/source acceptance.

    8. YYou / IT

      Only if separately opted in: review WSL features

      Terminal›Run Task›Install WSL components

      1. Native skips this scope. For approved WSL, use an approved Administrator context when required; no automatic elevation.
      2. Pause on pending restart, retain runtime/distros/data and never reset/update/launch a distro.

      Details: Phase 2: installed-first named modules · step 7

      You should see

      Optional WSL/component outcome, never a Native prerequisite.

    9. YYou / IT

      Decide optional modules, then observe outcomes

      Terminal›Run Task›Optional named module

      1. Ubuntu is separate after WSL readiness. Docker needs licensing; modernization is explicit Java 11 plus optional extension.
      2. Wait for a known vendor outcome; timeout/cancellation is uncertain, never a blind retry.
      !

      Finish setup/SkipBase are legacy-only after successful base plus reboot/resume, not stopped-partial recovery.

      Details: Phase 2: installed-first named modules · step 8

      You should see

      Retained tools/settings/accounts and a truthful per-module result.

    10. YYou / IT

      Refresh, verify Native and accept the intended profile

      Save/reopen when needed›Native Verify

      1. Require all 18 Native records PASS/exit 0 plus actual enabled profile/source acceptance.
      2. Keep full verification separate; Native never queries/installs WSL or converts full FAIL to success.

      Details: Phase 3: Verify and enterprise acceptance · step 9c

      You should see

      Positive Native prerequisites only; F5/helpers/live requests need separate acceptance.
