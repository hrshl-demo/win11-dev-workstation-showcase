    Architecture and lifecycle

    Ownership, architecture and financial invariants

    Ownership and lifecycle are explicit: human setup, human Restore, daily no-restore checks, scoped GitHub review and separately approved existing-AKS delivery.

    Documented⏱ Reference: no live operation$ No automatic actionsWorkstation showcase

    Copy-only instructions. Checkmarks are manual progress, not laptop verification.

    Recommendations and workspace settings do not enforce enterprise policy. Twelve required extensions and the optional thirteenth are accepted in the actual intended approved profile, not inferred from a list.

    The actual phase and approval flow

    1. Phase 0: actual prerequisites, policy/source/profile approval and safe clone review.
    2. Phase 1: read-only Preflight, optional pre-setup inventory gaps kept explicit.
    3. Phase 2: independently confirmed installed-first modules; no global tweaks or silent upgrades.
    4. Phase 3: save/reopen when needed, Verify and genuine profile/source acceptance.
    5. Phase 4: explicit human Dependencies Restore, then daily no-restore Test/Lint/Coverage.
    6. Phase 5: human local/debug/container launch only with existing prerequisites; real synthetic requests.
    7. Phase 6: separately authorized GitHub sign-in, diff, commit/publish/PR, review and exact-SHA CI.
    8. Phase 7: optional current-main manual request, modern gates, same-run image digests, independent approval and existing namespace deployment.

    Repository code readiness does not prove laptop readiness. Setup never authenticates/restores projects/launches/deploys. Push/PR never deploys. A stopped partial setup is neither successful base/resume nor a rollback.

    Exact money and sample contracts

    ContractInvariant
    ArithmeticDecimal/BigDecimal or exact integer/rational arithmetic; never binary floating point for money
    Rounding/serializationExplicit ROUND_HALF_UP/half-up; monetary JSON is fixed two-decimal strings
    INR displayIndian lakh/crore grouping, separate from numeric calculation
    Existing EMIRounded EMI times tenure defines total_payment; preserve it during schedule work
    Schedule exercisePreserve rounded EMI; prepayment after specified regular payment; shorten tenure, never reduce EMI; last installment equals remaining principal plus rounded interest
    IFSCSynthetic syntax-only normalization/validation; no bank/branch/account/payment existence proof
    FXFixed synthetic USD/EUR/GBP rates to INR, not market data; exact integer paise rounding
    PrivacyNo raw request/query logging; mask PAN/Aadhaar/mobile/account patterns and return safe stable errors

    The existing EMI rounded-total convention is not silently recalculated or clamped for tiny inputs. Edge validation/rounding boundaries and health need focused tests with every behavior change.

    Runtime, restore and failure boundaries

    • Auto selects wslc first; Docker is considered only if wslc is absent. Explicit selection probes only the approved selected runtime, never fallback after failure/denial.
    • Local image build/acquisition is only explicitly confirmed Restore ContainerImages. RunContainer inspects an existing image and uses --pull=never.
    • F5 requires existing pinned/approved debugger and project readiness, no hidden helpers or synchronization.
    • Missing prerequisites are NOT RUN. Offline mode alone does not prove no cached restoration.
    • Cleanup retains shared tools/accounts/distros/environments/modules/caches/source/cloud. It is not workstation uninstall or demo reset.

    Existing-AKS trust and safe source history

    Only current reviewed main can dispatch the protected manual delivery workflow. Modern CI and distinct identities precede same-run immutable digests; independently verified aks-demo review precedes namespace deployment. Unavailable/unverifiable live protections fail closed.

    Revised main has no Go serving-code exceptions. Deliberate query-logging/internal-error examples are isolated non-serving training text. Historical demo-baseline is retained but unsafe and never runnable/deployable; inspect demo-complete for the schedule fallback only.
